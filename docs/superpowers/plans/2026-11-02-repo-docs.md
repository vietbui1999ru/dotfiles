# Repository documentation companion integration plan

Status: draft integration plan; skill/templates and curated project index exist.
Related: [takeover plan](2026-11-02-claude-codex-takeover.md).

## Confirmed design

Git shares curated project history; runtime stays local. Canonical docs live in
the repo. Existing Pi workers execute bounded documentation assignments alongside
or after code, with a single docs owner and normal review. Existing docs-sync
and wiki Mintlify builder stay unchanged. New sites use a separately selected
renderer; the skill supplies a hostable information layout, not a running site.

Skill/template entry: [repo-docs](../../../shared/skills/repo-docs/SKILL.md).
Durable entry: [project work](../../project/index.md).

## Bounded remaining tasks

1. **Pilot existing docs worker.** Planner supplies code revision, task ID,
   exact pages, evidence and audience. Cheap worker uses repo-docs in separate
   worktree. Reconcile against final code; validate relative links/frontmatter,
   repo's build and actual Obsidian rendering if an explicit vault is available. Use a repo-root vault for this pilot because
   source-artifact links leave docs/; a docs-only vault does not resolve them.
   Keep new files in this branch until normal integration; do not run global
   bootstrap or change live agents from a feature checkout.
2. **Durable artifact capture.** Extend the approved context-switch work only
   after its contracts settle. Before any already-authorized cleanup, enumerate
   referenced specs/plans/handoffs and verify each durable copy/ref exists in
   committed feature history. Block pruning on unique unpreserved content.
   Preserve current active SPEC and final archive rules; never auto-approve or
   auto-publish. Test missing artifacts, dirty source, duplicate IDs and renamed
   archives. Checkpoints alone are not preservation. Runtime retention remains
   explicit user/workflow policy; do not install deletion automation by inference.
3. **Read-only local projection.** Reuse agent-session, pi-outcome, existing queue
   and pending review records. Write ignored main-root .agents/project-view/
   <worktree-id>/current.md with task links and observed-at/stale/unknown labels;
   atomic per-worktree writes, no shared index rewrite. Persist curated tasks
   separately under docs/project/tasks/. Test two worktrees, missing sources,
   pruning/reopening and no session/credential data in tracked docs. No second
   queue, locks, review decisions or status authority.
4. **Hosting adapter for chosen pilot repo.** Detect existing renderer; review
   page allowlist/navigation and private-link handling before building. Tests
   assert private tasks/specs/plans/runtime excluded, public links resolve, and
   canonical Markdown remains unchanged. A new framework requires explicit
   selection; publication remains an authorized external action. Do not reuse
   wiki-only Mintlify generator for unrelated repositories.

## Evidence and stop condition

Skill validator, link checks, shell syntax and isolated behavioral exercise
cover this package. They do not prove Obsidian reading-view or hosted rendering.
Manual pilot must verify both before claiming parity. No dedicated doc-agent
config is necessary unless measured repeated work justifies it; reuse worker
with skill and bounded scope. Model routing follows the takeover plan.
