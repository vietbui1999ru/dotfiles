# Guard Refusal Logging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The ref guard, pi-queue's worktree-busy check and Claude Code's built-in worktree guard each leave one redacted entry in the safety log, and every pi-queue `failed` event carries a reason.

**Architecture:** A new `safety-log record` subcommand is the one shared writer, in Python. The ref guard (POSIX sh), pi-queue (Python) and a new `PostToolUseFailure` hook call it, best effort. The readers learn a `noted` verdict that only the writer produces.

**Tech Stack:** Python 3 stdlib (`scripts/safety-log`, `scripts/pi-queue`, `unittest`), POSIX sh hooks, the session-band mod (TypeScript, `claude plugin test`).

**Spec:** `SPEC.md` (branch `feat/guard-log`, 14 ACs, approved). Read it with this plan.

## Global Constraints

- Logging is best effort: no guard's decision, exit code or stderr message changes, including when the log cannot be written.
- Redaction, the 4000-character cap (`…[truncated]`) and rotation at 2000 entries (`.jsonl` → `.jsonl.1`) match `claude/.claude/hooks/enforce-bash-safety.sh` exactly. Do not change that hook.
- Log location: `${SAFETY_LOG_DIR:-$HOME/.claude/state}`. Every test sets `SAFETY_LOG_DIR` (and `PI_QUEUE_STATE` for pi-queue) to a temp dir.
- New rule ids, exactly: `ref-guard`, `queue-worktree-busy`, `worktree-guard`.
- `noted` is written only by `safety-log record --noted`. `safety-log mark` keeps `choices=("ok", "false-positive")`.
- No new dependencies. Tests are stdlib `unittest`, run as `python3 -m unittest scripts.tests.<module>.<Class>.<test>`.

## Probe result (2026-11-03, Claude Code 2.1.317) — AC-9

- The built-in worktree guard's refusals fire **`PostToolUseFailure`** for `Bash`. The user-level `scripts/mistake-alert-hook.mjs` (already registered for that event) recorded `bash|git status|denied` at 13:45:13 and 14:02:09, the two probe runs of `git -C ~ status`. The plain `false` was recorded as `bash|false|other`.
- The payload, per `mistake-alert-hook.mjs`: `tool_name`, `tool_input.command`, `error` (the refusal text), `session_id`, `cwd`, `is_interrupt`, plus the standard `transcript_path`.
- Every refusal's text contains `is isolated in the worktree` and `Refusing to run it`; an ordinary failure such as `false` gives `Exit code 1`.
- `PermissionDenied` was not needed and is not registered.

## Review Focus

1. A secret inside a refused command, such as `GH_TOKEN=ghp_… git push` refused by the ref guard: the entry shows `[REDACTED]`. Test in Task 1 (the parity fixtures) and in Task 2 (one ref-guard case with a token in the command).
2. `safety-log` missing, not executable, or `python3` absent when the ref guard refuses: the commit is still refused with the same message and exit code 1. Test in Task 2.
3. A `noted` verdict on an entry, followed by `safety-log mark <id> false-positive`: the entry now counts in `--false-positives`, and the chip shows it as judged. Test in Task 1 (CLI) and Task 5 (chip).
4. A `PostToolUseFailure` for a non-Bash tool, or an interrupted command (`is_interrupt: true`) whose text mentions the worktree: nothing is logged. Test in Task 4.
5. The ref guard refusing inside `git rebase`, which sends many ref updates: exactly one entry, because the hook exits at the first refused ref. Test in Task 2.

### Task 1: `safety-log record` and the `noted` verdict

**Files:** Modify `scripts/safety-log`. Test `scripts/tests/test_safety_log.py` (new class `Record`).

**Interfaces:** Produces the CLI `safety-log record --rule R --reason TEXT [--command C] [--session S] [--cwd D] [--transcript T] [--noted]`. It exits 0 after writing and exits 0 on any write failure too (never raises), printing the new id on stdout when it wrote one.

  - `test_record_redacts_like_hook`: for each command in a shared `SECRET_FIXTURES` list, the `command` from `record` equals the `command` from `HookLog.run_hook`. Use one blocked command per fixture, so the hook logs it. Example: prefix each fixture with `rm -rf / ` or another command the hook blocks, and pass the same full string to `record`. Fixtures must cover every redaction form listed in `docs/workflows/bash-safety-log.md`: `ghp_`, `gho_`, `ghs_`, `github_pat_`, `sk-`, `Bearer`, `AKIA`, `NAME=value` with `TOKEN`/`SECRET`/`PASSWORD`/`PASSWD`/`KEY` in double, single and bare quoting, and `--token`/`--password`/`--passwd`/`--secret`/`--api-key`/`--apikey` with `=` and with a space.
  - `test_record_caps_and_rotates`: a 5000-character command is stored as 4000 characters plus `…[truncated]`. With a log already holding 2000 lines, the next record moves it to `.jsonl.1` and starts a new file holding one line.
  - `test_noted_verdict`: after `record --noted`, the verdicts file has `{"id": <id>, "verdict": "noted"}`. `safety-log --pending --json` omits the entry, and `safety-log show <id>` prints `verdict: noted`. `safety-log mark <id> false-positive` succeeds, after which `--false-positives` counts it. `safety-log mark <id> noted` exits non-zero.
