# Pi Pane Grid Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dispatched Pi panes sit two-even beside Claude, then fill even, width-sized grids in `pi`/`pi-N` and `verdict`/`verdict-N` tabs, with reliable labels and the three queue follow-ups.

**Architecture:** `scripts/pi-layout.mjs` gains pure planners (grid columns, where to add a tile, which tab of a series, which split ratios make tiles even) plus a small herdr socket client used only by its CLI. `scripts/pi-view` and `scripts/pi-pane-run` call the CLI; every herdr failure keeps today's fallback. The session-band mod learns pueue's Stashed state and template step order.

**Tech Stack:** zsh, Node `.mjs` with `node --test`, herdr 0.9.5 socket API (newline-delimited JSON at `$HERDR_SOCKET_PATH`), session-band mod (TypeScript, `claude plugin test`).

**Spec:** `SPEC.md` (branch `feat/pi-grid`, 17 ACs). Read it with this plan.

## Global Constraints

- At most 2 agent panes beside Claude (`MAX_AGENTS = 2`); Claude keeps `ANCHOR_SHARE = 0.6`.
- Grid columns: `min(3, floor(width / MIN_AGENT_WIDTH))`, at least 1; `MIN_AGENT_WIDTH = 40`, `MIN_AGENT_HEIGHT = 8`. Cap 6 tiles per grid tab (`GRID_MAX = 6`).
- Grid tab series: `pi`, `pi-2`, `pi-3`, … and `verdict`, `verdict-2`, … Tab labels carry no task ids.
- Running panes never move between tabs; a freed slot beside Claude is filled only by a new dispatch.
- Pane label: `pi#<task id> <slug>`; slug alone when the pueue lookup misses; never blank.
- No new dependencies, no long-lived process or event subscriber (spec: Ask first).
- Never edit a `verify:` line. Tests whose asserted behavior the spec changes (the 3-agent limit) are updated in the task that changes it, and the commit message says so.

## Facts established by probing herdr 0.9.5 (2026-11-01)

- Socket request: one JSON line `{"id":"1","method":"<m>","params":{…}}`; one JSON line back with `result` or `error`.
- `layout.export {tab_id}` returns `result.layout.root`, a binary tree: `{type:"pane",pane_id}` or `{type:"split",direction:"right"|"down",ratio,first,second}`.
- `layout.set_split_ratio {tab_id, path, ratio}`: `path` is an array of booleans from the root, `false` = `first`, `true` = `second`, `[]` = the root. `ratio` is the `first` child's share. The pane and its process survive; the response carries the new layout.
- `layout.apply` is **not usable**: it replaced the tab with a new tab id and new panes, killing their processes.
- herdr's `pane split` only splits a pane, so a new full-width row cannot be added. Grids are therefore built as columns: a `right` chain of columns, each column a `down` chain of tiles. Filling column by column in visual row-major order gives a row-major grid.
- herdr already binds `zoom = "prefix+z"` by default; `prefix+=` is unbound. Custom keys: `[[keys.command]]` with `key`, `type = "shell"`, `command`. `herdr config check` validates the file.

## Review Focus

1. pueue task id `0` is real (ids restart at 0 after `pueue clean`): `pi#0 <slug>` is a correct label, not a failure. Only a missing task falls back to the slug. (SPEC AC-10's "never `pi#0`" reads as "never a made-up 0"; flag to the human, do not special-case 0.) Test in Task 5.
2. `HERDR_SOCKET_PATH` unset or the socket refusing: every new CLI subcommand exits 1 with no output, and `pi-view` keeps today's placement (pi tab, stack down). Test in Task 1.
3. A grid tab whose tree is not the column shape (a person split a shell in it, or closes left a nested tree): `planGridAdd` still returns a split of an existing leaf, never throws, and rebalance still evens every chain. Test in Task 2.
4. A tab narrower than 40 columns: one column; a tile that would fall under `MIN_AGENT_HEIGHT` makes the tab full, so the next tile goes to the next tab in the series. Test in Task 2.
5. Two dispatches at once: the grid decision, split and rebalance all run inside `open_pane`'s existing flock, so two runs never take the same slot or both create `pi-2`. Covered by keeping the calls inside the lock in Task 3 (live check AC-15).

- [ ] **Step 2: Run** `node --test --test-name-pattern="rebalance" scripts/pi-layout.test.mjs`. Expected: FAIL, `rebalancePlan` is not exported.

- [ ] **Step 3: Implement**

The weight of a node along a direction `d` is the sum of its children's weights when it is a split in direction `d`, and 1 otherwise. For every split (depth first, `first` before `second`), the target ratio is `w(first) / (w(first) + w(second))` along the split's own direction. A split whose subtree contains a pane in `keep` is skipped, but its children are still visited. Emit only when `|ratio - target| > 0.01`.

`herdrRequest` uses `node:net` against `process.env.HERDR_SOCKET_PATH`: it writes one JSON line, reads up to the first newline, resolves `result`, and resolves `undefined` on `error`, a missing socket or a 3 s timeout.

The CLI `rebalance <tab id>` runs `layout.export`, then one `layout.set_split_ratio` per planned entry, and exits 0. `--focused` takes the tab with `focused: true` from `tab.list` (`herdrRequest("tab.list", {})`). The CLI only acts on a tab whose label matches `/^(pi|verdict)(-\d+)?$/`; any other tab exits 0 untouched. Keep the existing `main` path for `auto|side|below|tab`.

- [ ] **Step 2: Run** `node --test scripts/pi-layout.test.mjs`. Expected: the new tests FAIL.

- [ ] **Step 3: Implement**

- Set `MAX_AGENTS = 2` and add `GRID_MAX = 6`.
- Columns are the leaves of the root's `right` chain; a non-`right` root is one column. The tiles of a column are the leaves of its subtree.
- `planGridAdd` returns `full` at `GRID_MAX` leaves, or when the tallest column after the add would give a tile under `MIN_AGENT_HEIGHT` rows. Otherwise:
  - with fewer than `gridColumns(width)` columns and a rightmost column that is a single pane, split it `right`;
  - else split the bottom (last) leaf of the shortest column (leftmost on a tie) `down`;
  - for an unrecognized shape, split the last leaf `down`.
- `pickGridTab` walks `seriesLabel(series, 1..)` in order and returns the first tab with room. When none has room, it returns `new-tab` with the first missing label.
- CLI `grid`: `tab.list` for the workspace, then `layout.export` plus area per series tab. Area comes from `herdr pane layout --pane <any pane>`, as `readLayout` does today.
